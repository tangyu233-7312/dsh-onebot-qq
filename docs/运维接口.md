# 可选运维外设（ops provider）

> 一句话：**本包不提供** systemd unit / cron / 站点自检脚本；这些属于「某台机器」的运维，
> 以**可选 ops provider** 的形式外挂。没有它，控制台里相关动作只会提示「本机未配置运维能力」，其余功能完全正常。
> （长期记忆的自动整理由 long-memory 插件自己做、直连用户填的接口，不经过 ops，也不在此列。）

## 一、哪些东西不进包

| 能力 | 为什么不进包 | 不进包时的行为 |
|---|---|---|
| `systemd` 服务探活 / 重启 | 部署形态是 in-process，进程由 DSH 管；不同机器服务名不同 | 控制台显示未配置 |
| cron / 定时任务（清理、告警等站点自有任务） | 站点私有脚本；包内禁止 `child_process`/cron/bash（内部定时器只用于长期记忆的定时整理） | 相关动作返回「未配置」 |
| 站点自检（selfcheck） | 每台机器检查项不同（协议端如 SnowLuma、OneBot 等实现、DSH、日志路径…） | 控制台按钮返回「未配置」 |
| QQ 登录（扫码/账密） | 与协议端（OneBot v11）部署方式强相关，且涉及账号凭据 | 控制台「登录」走 ops；未配置时提示 |
| 临时文件清理 / 备份清理 | 站点磁盘策略不同 | 动作返回「未配置」 |
| （原「群记忆积累」） | **2026-11-09 起已下线**：`group-memory` 被 `long-memory` 取代，记忆由插件自己写、自己整理（直连你在「记忆」页填的接口） | 不需要 ops，也没有对应动作 |

> 这些脚本放在**你自己的运维机**上即可（cron、systemd、crontab、计划任务都行），
> 只要它们操作的是本实例的数据目录/日志目录，不需要改动本包。

> **命名口径**：给人看的和机器侧的名字**都已统一成「OneBot」** —— 页签「OneBot 连接」、按钮「测试 / 重新连接 OneBot」、动作 id `onebot-check` / `onebot-reconnect`、配置键 `onebot.*`、日志前缀 `[onebot-qq:onebot]`。旧版配置的 `napcat.*` 仍会被自动读取（`loadConfig` 兼容），升级不用改文件；自建脚本若 grep 过旧日志串请改成 `OneBot WS 已连接`。**实际探测的是当前协议端** —— 任意 OneBot v11 实现（如 SnowLuma）均可：接法一样，都在「OneBot 连接」页填地址/token（SnowLuma 的 3000/3001 强制带 `accessToken`，两个都要填）。

## 二、ops provider 接口

内核启动时可选加载一个 **`ops.local.mjs`**（站点私有文件，**.gitignore，不进包**），
默认导出（或命名导出）一个工厂函数，返回带下列可选方法的对象；不实现的方法保持 `null`：

```js
/** ops provider 契约（所有方法都可选）。返回值会原样进入控制台 RPC 响应。 */
export default function createOps({ log, env, dataDir }) {
  return {
    // 站点自检：返回 { ok, checks: [{ name, ok, detail }] } 或任意可读对象
    selfcheck: async () => ({ ok: true, checks: [] }),

    // systemd 探活（站点为 standalone 形态时才需要；in-process 可留 null）
    systemdProbe: async () => null,

    // 清理临时文件：返回 { ok, removed, bytes } 之类
    cleanup: async (_payload) => ({ ok: false, error: '本机未配置运维能力（cleanup）' }),

    // 备份/重复会话清理
    dedup: async () => ({ ok: false, error: '本机未配置运维能力（dedup）' }),

    // 站点级人设切换（控制台「人设」页的扩展动作；包内 `bin persona` 已覆盖常规需求）
    personaSwitch: async (_name) => ({ ok: false, error: '本机未配置运维能力（personaSwitch）' }),
  }
}
```

> 2026-11-09 起「群记忆」整体下线（`group-memory` → `long-memory`），`memoryAccumulate` 这个 ops 能力也随之不再被调用：想换分析流程请直接改插件里的整理提示词 / 接口。

加载方式：环境变量 **`DSH_QQ_OPS`** 指向你的 provider 文件（绝对路径），例如：

```bash
# Linux/macOS（写进 dsh-web 的启动环境，不要写进仓库）
export DSH_QQ_OPS="$HOME/.dsh/dsh-onebot-qq/ops.local.mjs"

# Windows PowerShell
$env:DSH_QQ_OPS = "$env:USERPROFILE\.dsh\dsh-onebot-qq\ops.local.mjs"
```

未设置或加载失败时，内核使用「空 provider」（所有能力为 `null`），只记一条 debug 日志。
控制台调用对应动作时返回 `{ ok: false, error: '本机未配置运维能力…' }`，**不会抛 500、不会影响聊天**。

## 三、`ops.local.mjs` 示例骨架

放在 `<dataDir>/ops.local.mjs`（已在 `.gitignore` 的 `ops.local.mjs` 规则里；也可放任意位置用
`DSH_QQ_OPS` 指过去）：

```js
/**
 * 站点私有 ops provider 示例骨架。
 * ⚠️ 这是你自己的文件，不进包、不进 git；包内的跨平台纪律不约束它，
 *    但请自己注意：命令注入、凭据脱敏、最小权限。
 */
import { execFile } from 'node:child_process'
import { promisify } from 'node:util'

const run = promisify(execFile)

export default function createOps({ log = console, env = process.env, dataDir = '' } = {}) {
  return {
    // 例：探活一个 systemd 服务（仅当你的部署确实是 systemd 形态）
    systemdProbe: async (unit = 'dsh-web') => {
      try {
        const { stdout } = await run('systemctl', ['is-active', unit])
        return { ok: true, unit, state: stdout.trim() }
      } catch (e) {
        return { ok: false, unit, error: String(e.message || e) }
      }
    },

    // 例：清理自己的临时目录（务必只清确认过的路径）
    cleanup: async () => {
      log.info?.(`[ops] cleanup requested for ${dataDir || '<dataDir>'}`)
      return { ok: false, error: '示例骨架：请按你的站点实现 cleanup' }
    },

    // 例：自检（返回给控制台展示）
    selfcheck: async () => ({
      ok: true,
      checks: [
        { name: 'ops.local.mjs 已加载', ok: true, detail: '' },
        { name: 'example: 自定义检查', ok: true, detail: 'replace me' },
      ],
    }),
  }
}
```

> 也可以只实现你在用的方法（其余不返回）；内核对缺失方法按「未配置」处理。

## 四、与 `:3971` 兼容网关的区别

- **ops provider**：控制台/内核的**可选能力**（自检、登录、清理…），没有就降级提示。
- **compat gateway**：给旧脚本用的 HTTP 兼容层（`/health`、`/send`、`/send-image` 等），
  由 bundle 配置 `compatServer: true` 打开，默认关闭。两者互不依赖。

## 五、写给站点维护者

- 所有 ops 文件（`ops.local.mjs`、cron 脚本、selfcheck、systemd unit）**都不进包**，也不要在 docs/examples 里写真实机器路径。
- 想把某项能力做成通用功能：应该以**子插件**（`plugins/<id>/`）形式进包，而不是塞进 ops。
- 升级本包不会覆盖 `ops.local.mjs`（它在数据目录，不在包内）。

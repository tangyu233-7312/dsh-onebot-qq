> 这两块都**不在上游**，是本 fork 加的。两边都**默认关**，装好不会自己动。
> 上游地址：<https://github.com/YUsaltyfish/dsh-onebot-qq>

## 一、语音 / 曲库 / 唱歌（plugins/voice）

把话念成语音，或者直接唱一首歌 —— 音色是**你自己训练的 RVC 模型**。

### 默认状态：全关

| 开关 | 默认 | 说明 |
|---|---|---|
| 子插件本身 enabled | **关** | 关着时整个插件不加载，speak / sing 两个工具都不注册 |
| 语音输出 ttsEnabled | **关** | 打开后模型才能调 speak 把话念出来 |
| 唱歌 singEnabled | **关** | 打开后模型才能调 sing 点歌 |

**三个都要开才会用。** 之所以默认全关：它依赖 Python + ffmpeg +（唱歌还要）RVC 与 CUDA ——
没配好就开着一堆工具，每次调用都报错，比没有更烦。

### 两条链路

   语音输出  文本 → TTS（edge 或 MiMo）→ RVC 换音色 → ffmpeg 转 24k 单声道 → silk → QQ 语音
   唱歌      曲库找歌 → Demucs 分离人声/伴奏 → RVC 只换人声 → 混回伴奏 → mp3 → silk → QQ 语音

**为什么说话也要过 RVC**：MiMo 的 voicedesign 每次调用都重新生成音色（实测同一段描述三次，f0 差 8.8%），
群聊里听着像三个人轮流说话。RVC 是**给定样本固定复刻**，所以音色身份必须落在 .pth 上，
TTS 只负责「说什么、怎么说」。

### 要装什么

| 项 | 必需？ | 说明 |
|---|---|---|
| **Python 3.10** | 是 | TTS 脚本要用。唱歌的 RVC **必须 3.10** —— 3.11 起 fairseq/hydra 的可变 dataclass 默认值会直接报错 |
| edge-tts、pysilk | 是（TTS） | pip install edge-tts pysilk。edge 免费无 key |
| **ffmpeg** | 是 | 转码与分离要用。也可以让 imageio-ffmpeg 自带一份 |
| **RVC 能力包** | 唱歌要 | 见下节，仓库给脚本、**模型自备** |
| **NVIDIA 显卡 + CUDA** | 唱歌推荐 | 没显卡也能跑 CPU，**慢十几倍**（一首歌几分钟到十几分钟） |
| MiMo API Key | 可选 | 想用 voicedesign 音色设计才要。edge 不需要 |
| 磁盘约 6–10 GB | 唱歌要 | 主要是 torch |

### 怎么搭（唱歌）

    # 1. 进仓库里的能力包目录
    cd tools/singing-pack

    # 2. 一键装环境（建 .venv + 装 rvc-python、imageio-ffmpeg）
    install.bat                有 N 卡
    install.bat --torch-cpu    没独显
    ./install.sh               Linux / macOS

    # 3. 放音色（自己训练的，仓库不含）
    #    voice-models/你的音色.pth
    #    voice-models/你的音色.index   ← 可选但强烈建议

    # 4. 自检
    .venv/Scripts/python python/rvc-infer.py info
    #   看 "ok": true 与 "cudaAvailable": true

然后把这三个路径填进控制台**「运维」页**（语音插件自己的运维页签，不是「语音与唱歌」里的分组 —— 2026-10-30 界面归并后这两个是分开的两个页）：

| 配置项 | 填什么 |
|---|---|
| TTS 用的 python | 装了 edge-tts + pysilk 的那个解释器，如 C:/Python310/python.exe |
| RVC 用的 python | tools/singing-pack/.venv/Scripts/python.exe |
| RVC 能力包目录 | tools/singing-pack 的绝对路径 |

> 路径一律用**正斜杠**（C:/...），反斜杠在 JSON 里要转义，容易出错。

### 曲库

三处来源，都在插件里：

1. **群友/私聊直接发音频** —— autoLibrary 开着时自动收进曲库（默认开）
2. **B 站下载** —— 点歌时本地没有，biliFallback 开着就去 B 站搜并下音频（用 yt-dlp，默认开）
3. **手动放** —— 丢进 musicDir

曲库目录默认 <数据目录>/music_mp3，控制台可改。

### 已知限制（实测，不是 bug）

| 现象 | 原因 |
|---|---|
| 女声歌 pitch 超过 +4 反而更差 | RVC 的硬上限：+6 的 f0 比 +4 还低。男声歌 +8 到顶 |
| 和声/叠唱段会「突然变成啊~~」 | RVC 的 f0 跟踪假设单音高，遇到复调会在两者间跳。架构限制 |
| 没 N 卡时一首歌很久 | CPU 推理，慢十几倍 |
| 音色不像 | 先检查 .index 放没放；再调 --index-ratio（0.75 起步）与 --protect |

## 二、解析侧车（sidecar/）

「链接解析 / 看视频 / 看视频链接 / 自己找视频看」这四个功能的**下载与抽帧后端**。

### 为什么是独立进程

插件跑在 DSH 进程内，而包内红线**禁止 child_process**；
下载视频、调 ffmpeg 必须起子进程 —— 所以挪到进程外，插件只发 HTTP。

这就是 sidecar（侧车）模式：主程序旁边挂一个专职小服务。

### 默认状态：不启动

- **本仓库不帮你启动它**。要么双击 sidecar/start.bat，要么装成开机自启（install-autostart.ps1），要么用 systemd
- 插件侧：link-parser 默认**关**；video-read / video-link-read 默认开，
  但**侧车不在时会自己降级**（群里如实回一句「看视频的服务没起来」）

### 要装什么

| 项 | 必需？ | 说明 |
|---|---|---|
| Node.js 18 或更高 | 是 | 侧车是零依赖的 .mjs，只用内置模块 |
| **ffmpeg + ffprobe** | 是 | 抽帧/转码。sidecar.config.json 里可指定路径，留空则自动找 |
| **yt-dlp** | 链接解析要 | B站/抖音下载。可给可执行文件路径，或配 pythonPath 用 python -m yt_dlp |
| 磁盘 | — | 下载的视频按 TTL 自动清（默认 10 分钟帧、2 GB 上限） |

### 启动

Windows：

    cd sidecar
    start.bat                 前台跑，关窗口就停
    install-autostart.ps1     装成开机自启（计划任务）

Linux：

    cd sidecar && node server.mjs
    # 或写个 systemd：ExecStart=/usr/bin/node /path/to/sidecar/server.mjs

自检：

    curl http://127.0.0.1:3972/health
    # 期望 {"ok":true,"ffmpeg":true,"ffprobe":true,"ytdlp":true,...}

### 三个接口

| 接口 | 谁用 | 做什么 |
|---|---|---|
| GET /health | 控制台/自检 | 报 ffmpeg / yt-dlp 是否就位 |
| POST /read | video-read / video-link-read / video-wander | 下载（或本地路径）→ ffprobe 探时长 → ffmpeg 抽 N 帧 → 返回帧路径 |
| POST /parse | link-parser | 下载媒体 → 返回本地路径（由插件搬进群） |

### 安全边界（改之前先读）

侧车是**群友能间接触发**的（发视频、贴链接），所以：

- **只绑 127.0.0.1**，不对外网开
- **域名白名单** allowedHosts：B站/抖音/QQ 的 CDN 在列，其它一律拒
- **私网地址拒绝**：不许它去访问内网（防 SSRF）
- **本地路径白名单**：只读临时目录与 .dsh/dsh-onebot-qq 下的文件
- **失败一律 200 + ok:false**：让插件能干净降级，不是抛 500 让调用方猜
- **用完就删**：源视频几百 MB，按 TTL 与总量上限清

### 看视频的几个参数（都在控制台「文件与图片」页）

| 项 | 默认 | 行为 |
|---|---|---|
| **最长看多久的视频** | 600 秒 | 超了**直接不看**（只给标题简介）。⚠️ 侧车也认这个值——早先它只用自己的配置，控制台调多大都没用 |
| **短视频抽几帧** | 8 | ≤「多长算长视频」时用 |
| **长视频抽几帧** | 11 | 超过阈值时多给几帧 |
| **多长算"长视频"** | 600 秒 | 默认 10 分钟 |
| **上一条视频能"接住"多久** | 120 秒 | QQ 里"发视频"和"@它"必然是两条消息，这个窗口让第二条接住第一条 |
| **等侧车的超时** | 180 秒 | 侧车要下载+抽帧，短视频 6~12 秒 |

> 帧数有硬上限 24（侧车侧），防「填个 999 把侧车挂在那儿」。
> **每帧 = 一次图片输入**，帧数直接等于成本。

### 判定过程有日志

想弄明白「为什么这条没看成」，看这几行（`info` 级，默认可见）：

```
[看视频] group:xxx 进入：wake=at replyTo=1234567890
[看视频] group:xxx 跳过：没叫它（onlyWhenAddressed）
[看视频] group:xxx 跳过：无视频段/无引用/窗口关
[看视频] group:xxx 放弃：三条来路都没找到视频段
[看视频] group:xxx 命中：来源=引用反查(内核)
[看视频] 请求侧车：https://…（qq）
```

三条来路是：**本条消息带视频 / 上一条消息刚发过 / 引用反查**。

### 常见问题

| 现象 | 处理 |
|---|---|
| Requested format is not available | B 站有些稿件没有低分辨率格式。本仓库已改成 -S res:480 排序（不是硬过滤） |
| QQ 群文件的视频下不了 | QQ 的 CDN 直链要走 directDownload，且域名要在 allowedHosts 里 |
| 抖音下载失败 | 需要 cookie：sidecar.config.json 里配 cookiesFromBrowser 或 cookiesFile |
| 抽帧是黑的 | 视频前几秒是黑场。正常，帧按时间均匀取 |

## 三、自己找视频看：两种触发方式

这个不需要额外装东西，但用法值得说清楚。

| 触发 | 谁决定 | 结果发到哪 | 冷却 | 每天上限 |
|---|---|---|---|---|
| **定时器**（自动看） | 时间到了 | 主人私聊 | 「多久看一次」（默认 4 小时） | 「每天最多看几次」（默认 6） |
| **对话里**（`watch_video` 工具） | 模型自己判断 | 主人私聊 | 「对话里看完后冷却」（默认 30 分钟） | 「对话里每天最多看几次」（默认 6） |

两条路走同一套观看逻辑：挑视频 → 侧车下载抽帧 → 起一轮模型写感想 → 发主人私聊。

> **两套配额完全独立**（2026-10-29 改）。
> 原来共用一份：定时器刚看完 → 你在聊天里让它看 → 它回「刚看过，N 分钟后再来」，
> 体感是「根本不是我要它看，是插件硬塞给我的」。现在定时器看它的，对话看对话的，
> 各算各的天数、各算各的间隔，唯一的共享是**同一时刻只能看一个**（运行锁）。

### 对话里怎么用

它在一轮正常对话里可以自己说「我去翻翻」，然后调 `watch_video`。
工具**立刻返回**（不等结果），这一轮先把话说完；几十秒后感想会另外发到主人私聊。

会拒绝的情况（工具如实返回原因，模型照实说）：

| 情况 | 返回 |
|---|---|
| 正在看别的 | 正在看别的，等这次看完 |
| 今天配额用完 | 今天已经看了 N 个了，配额用完了 |
| 距离上次太近 | 刚看过，N 分钟后再说 |
| 侧车没配 | 侧车没配，看不了 |
| 在「看视频的地方」会话里 | 不能再触发一次（防递归） |

> `autoEnabled`（自动看）关着**只挡定时器**，不挡对话里主动看 —— 在聊天里让它看，它就该看。

### 看视频那段提示词也能改

「自己找视频看」页有一项 **「看到画面后让它怎么想」**（多行文本）：

> 下面这些图就是这个视频的画面。**只看你看得见的**：画面里有什么、在讲什么、你的感觉。
> 看不清、看不懂、觉得无聊 —— 都可以直接说，别编画面里没有的东西。
> 写完感想还可以附带一句想对主人说的话。

- 整段会用原样拼进 prompt（换行保留）
- 想让它多抒情、少点分析、或者要求它跟主人说一句话，都改这里
- **清空 = 回落默认**（不会变成「没有任何要求」）

### 提示词：可以在控制台改

主动开口 / 续聊时给模型的提示，**不写死在代码里** ——
控制台「主动接话」页最下面有个「提示词（可改）」分组，六个文本框：

| 配置项 | 什么时候用 |
|---|---|
| 私聊主动开口时给它的提示 | 对方安静够久、它准备主动开口 |
| 私聊续聊时给它的提示 | 它刚在私聊回过话、对方又说了几句 |
| 群聊主动开口时给它的提示 | 群里没人叫它、它自己准备接一句 |
| 群聊续聊时给它的提示 | 它刚在群里回过话 |
| 私聊提示的收尾一句 | 贴在 prompt 最后一行 |
| 群聊提示的收尾一句 | 同上 |

- `{n}` 会替换成「这期间的新消息条数」
- 改完直接生效，不用重启
- 默认值就是原来写死的那几句，**你可以整段重写**（比如删掉某句叮嘱、换语气、去掉提到的工具）

### 默认文案：群聊与私聊是两套

主动开口轮（`proactive`）与续聊轮（`continuation`）的提示词**按场景分开写**：

| 场景 | 怎么要求 |
|---|---|
| **群聊** | 「不发也要在正文写一行 `[不发]` 原因」—— 群里没人点它名，只写正文等于石沉大海 |
| **私聊** | 只要求「想说话就调 send_message；不想说就不发，不用解释」—— 一对一里这次不想说话很正常，硬逼它解释反而像客服 |

> 这两套的**具体措辞**就是上面那六个配置项的默认值，都可以改。

私聊那版还会提一句「想找话题可以调 `watch_video`」，所以它会自己想到去看点东西。

> 曾经做过错的版本：`format.js` 的唤醒标记与尾部提醒都写死群聊口径，
> 私聊主动接话时模型看到「群里正聊着」「发到群里必须调 send_message」，
> 在只有两个人的私聊里完全是错位的。现在标记只留 `[主动开口轮]` 这种极简标签，
> 具体口径统一由 `index.js` 的 hint 按场景给。

## 四、这些跟上游的关系

| | 上游有吗 | 本仓库 |
|---|---|---|
| plugins/voice（语音/曲库/唱歌） | 没有 | 有，默认关，模型自备 |
| sidecar/（解析侧车实现） | 没有（上游只留接口约定） | 有，整套实现 + 配置 |
| tools/singing-pack/（RVC 推理脚本） | 没有 | 有，只有脚本，**不含模型** |

上游把这些当「外部依赖」让你自己准备；本 fork 直接把可用实现放进来了。

**升级上游时注意**：这几块不冲突（上游没有同名目录），
但 plugins/voice 里的路径配置与 sidecar/sidecar.config.json 是你的本机设置 ——
如果哪天上游加了同名文件，git merge 时才会需要处理。

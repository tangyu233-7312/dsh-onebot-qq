# 一个脑子：跨会话流水账 · 人设版本 · 当场看视频

> 2026-10-30。这篇说明**为什么这样设计**，以及改之前必须知道的三个坑。
> 配置项见 [配置参考.md](配置参考.md)，装法见 [安装与卸载.md](安装与卸载.md)。

## 一、要解决的问题

DSH 的会话是**一条 QQ 线一个**（`chatKey → sessionId`）。所以：

- 它在群里看到的事，私聊里的它不知道；
- 它在「看视频的地方」看完、写完感想，主对话里只有一句「我去翻翻」；
- 它写完说说，问它「写了吗」，它答不上来。

用户的原话是「像有不同人在做」。这不是模型笨，是**没有跨会话的自我**。

## 二、三条落地方式

### 2.1 流水账（`kernel/self-log.js`）

```
<dataDir>/state/self-log/YYYY-MM-DD.jsonl
{"ts":…,"at":"12:34","kind":"watch","what":"看了 B 站视频「星布谷地」","why":"我自己想看的","where":"私聊","channel":"master"}
```

| 设计 | 为什么 |
|---|---|
| **只记事实**（what/why/where），不记聊天正文 | 记正文 → 日志变成垃圾场 + 泄密风险 |
| **例外：看视频的感想留原文**（`thought`，≤600 字） | 那是它自己的产出，不是别人的聊天；只留 60 字摘要会出现「私聊追问只剩标题」 |
| **按天分文件**，append 时顺手清理（默认 7 天） | 不需要额外定时器；文件不会无限长；与帧、感想同一个保留期 |
| **写失败永不抛** | 记账失败不能影响"看视频"这件正事 |
| 由内核在 `before-turn` 注入 | 插件不用各自拼提示词；一处改、处处生效 |

> ⚠️ 注入的粒度是**按会话分**的：私聊给完整一行（`[我今天的经历] …`），
> 群里只给极简一句且注明「跟这个群无关，别主动说出来」。
> 给全会让它在群里自曝私聊；一点不给又前后不一致。这是折中，别随手改成"都给"。
>
> ⚠️ **没交感想的记录会打戳**：`看·无感想（只记了标题）`。
> 没有这个戳，它会把「只看见标题」说成「我看过」，然后照着标题编画面。

### 2.2 人设版本化（`plugins/persona-version`）

命名：`<角色><YYYYMMDD>.md`，同日多次改 → `-2`、`-3`。文件名排序 = 时间排序。

**为什么必须"另存新版本"而不是"原地改"**：

DSH 的 `@deepseek-ai/dsh-agent-instructions` 是**按路径 + 内容 digest 缓存**的 ——
"路径没变 + 内容没变就不重复注入"。它自己改文件走的是工具调用，不一定触发 DSH 记录的
`read/write/edit` touch，于是会出现「改了没生效」。另存新版本 → 指针换路径 → 一定重读。

四个工具：`persona_revise`（开新版本）→ `persona_write`（写正文）→ `persona_switch`（生效）→ `persona_history`（看历史）。

### 2.3 当场看视频（`watch_now`）

| | 旧 `watch_video` | 新 `watch_now` |
|---|---|---|
| 在哪看 | 另一个会话「看视频的地方」 | **当前这一轮** |
| 它看见画面了吗 | ❌ 只有那句「我去翻翻」 | ✅ 帧挂在下一轮 |
| 谁写感想 | 工具返回 → 插件转述 | **它自己说** |

实现关键：工具把抽好的帧 push 到 `turnCtx.nextImageParts`，
内核在**下一次 prompt**时挂上并**取空** —— 只给一轮，不会每轮重发同一批帧。

## 三、三个必须知道的坑

### 3.1 `_wakeKind` 只存在于合成轮

区分「它自己起的念」和「主人叫它看」，**不能只看 `_wakeKind`**：
那是 `runProactiveTurn` 贴的标记，主人正常说话触发的轮它是空的。
只看它 → 主人叫它看也会吃自己的冷却（线上原话：「看来冷却也管着本鱼自己点的」）。

现在内核每轮都贴 `_triggeredBy`（`master` / `other`），插件按它判。

### 3.2 定时主动接话两处开关容易互相吃掉

原来的写法是 `if (群冷场) … else if (私聊冷场)` —— 群冷场默认开着，**私聊永远不会触发**；
另外装定时器还要求 `privateFriendsOnly === false`，而控制台默认勾着「只对好友」→ **定时器压根不装**。
两处都有回归测试，且验证过「回退修复 → 测试变红」。

### 3.3 说说绕过了六项脱敏

红线是「文本只走 `deliver()`」，但 `sendQzoneMsg` 原来声明"不脱敏"，而 qzone 直接调它。
群里发错还能撤回，**空间发出去是公开的、收不回来**。现在适配器内部过同一份 `sanitizeSensitive`。

## 四、怎么验证

```bash
# 单元 + 集成（含本节所有回归）
npm test

# 打包卫生 + 仓库卫生（后者把 test/ 也扫一遍）
npm run check
```

覆盖率要点：

| 测什么 | 文件 |
|---|---|
| 流水账读写 / 坏行 / 不抛 | `test/audit-self-log.test.js` |
| 内核注入（私聊完整 / 群极简 / 空不注入） | `test/audit-self-log-kernel.test.js` |
| 人设版本（另存 / 不改旧版 / 群拒绝 / 自动升级） | `test/audit-persona-version.test.js` |
| 看视频分通道 / 当场看 / 主人不吃冷却 | `test/audit-video-wander.test.js` |

| 说说脱敏 | `test/audit-qzone-sanitize.test.js` |

## 五、上线到 NAS 的三处环境差异

代码功能一致，但 NAS 上有三处**历史命名/遗留文件**不能整包覆盖：

| 项 | NAS | 仓库 |
|---|---|---|
| 连接器文件名 / 类名 | `kernel/napcat-adapter.js` / `NapCatAdapter` | `kernel/onebot-adapter.js` / `OneBotAdapter` |
| 表情包库实现 | `vendor/dsh-sticker-shelf.mjs` | `plugins/stickers/shelf.js` |
| 侧车运维 | `plugins/sidecar-control/` | 无（本仓库不带） |

**部署时**：把 `onebot-adapter.js` 的**内容**写到 NAS 的 `napcat-adapter.js`，
并把里面的 `export class OneBotAdapter` 改成 `export class NapCatAdapter`（**两边都要改**，
只改 import 会报 `does not provide an export named`，2026-10-30 踩过）。

## 六、已知边界

- 流水账**不记聊天正文**，要追溯请翻 `logs/qq_chat/`
- `bot.deliver` 只出站、**不插话**：看完视频那条结果不会触发新一轮（否则它会自己跟自己聊起来）
- 人设版本目前只存整份文件 + 一行版本记录，不存 diff
- 群里只有它自己（+主人）时适合当"账本群"；有别人在群里就会对着别人说，账会乱

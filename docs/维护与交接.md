# 维护与交接

先读 [文档总览](README.md)，再按任务读 [开发指南](开发指南.md)、[安装与卸载](安装与卸载.md) 或 [排错](排错.md)。旧快照和历史结论只解释当时的决定，执行操作前以当前代码、配置和运行状态为准。

## 先分清维护对象

| 对象 | 维护时关注什么 |
|---|---|
| Git 仓库 | 代码、通用文档、可公开的示例；记录分支、提交和工作区差异 |
| 安装副本 | 实际被 DSH 加载的包；同机可能同时存在 profile 和宿主安装副本 |
| 实例数据 | 配置、人设、记忆、会话、聊天留档和媒体；不随代码整包覆盖 |
| 算力服务 | 生图、语音、唱歌的独立后端；后端在线不代表 PC QQ 机器人在线 |

多机部署时先确认哪个是主实例。需要以现网为准，就先读回差异再合入仓库。未运行的备用机器人只核对文件，不为证明同步而启动它。

## 修改、同步、验收

1. 核对工作区和现网，保存本次需要的备份，确定实际加载的所有安装副本。
2. 在仓库修改并运行适用测试；精确暂存任务文件，检查差异后提交。
3. 用站点部署脚本预览，再同步各安装副本。部署清单、路径转换和校验器应共用规则。
4. 逐文件核对内容；若部署会转换换行、旧适配器文件名或类名，按同一转换计算预期值。只数文件、目录或插件不能证明一致。
5. 对原本运行的实例，按变更需要重启并核验；代码发布与数据迁移分别记录。

站点若维护“仓库 + PC + NAS”三处，NAS 有两份安装副本时，两份都必须检查。通过状态报告明确列出每份的缺失、差异和额外插件；同步不要顺便清理未知文件。

本包使用 `kernel/onebot-adapter.js`。个别旧安装可能保留其他适配器名称；只有确认站点有该转换约定才使用，不对新安装自动改名。

**进程 active 不等于机器人正常。** 核验正在运行的实例至少检查：本次启动记录、插件加载错误、OneBot 连接及 QQ 登录状态。没有本次启动标记时不能拿旧日志证明成功；部署失败后即使回滚成功，也应返回失败状态并记录回滚结果。

只改通用文档或仓库检查脚本，不需要重启机器人。站点服务管理接口见 [运维接口](运维接口.md)；站点路径、凭据和服务脚本保留在部署机。

## 只读核验的边界

只读检查可以读取文件、状态和日志；不发 QQ 消息，不调用模型、生图、重置会话或重启服务。`refine_image_prompt` 会调用配置的模型，可能产生费用，不能作为免费的只读连通性探测。

提示词或人格改动还要核对实际生效的内容：

- 系统 prefix 可能来自 bundle patch、profile 或实际 preset，不能只看一个配置文件。
- 人设源文件、投递到 workspace 的文件和旧会话缓存分别检查。copy 需要重新投递，symlink 需要核对目标；不要顺便切换其他实例的人格。
- 文件一致不能单独证明旧会话已经使用了新提示。需要更新会话时，先明确影响，再按实际需求处理。

## 交接材料保持简短

入口只留最近一次带日期的核验、关键路径和任务导航。长期规则、当前待办、历史解释分开存放；同一事实只维护一处，其他地方链接过去。

- 插件由 `plugins/<id>/index.js` 发现，控制台按功能归组，插件数与页签数不是一一对应。
- 长期记忆已有衰减实现，旧 `group-memory` 已被替代；不要照旧待办另加一套。
- 历史 PR 状态、模型候选和旧运维命令注明日期，不当成当前结论。
- 清理前盘点归属、大小、引用及完整副本，确认清单后再执行。用户数据、修复备份和回收站另行处理。

## 发布到 Git 前

公开内容只保留可复用的说明、代码和占位示例。机器地址、用户名、QQ/群号、token、密钥、实例配置、聊天记录、音色和历史备份留在站点。旧文件即使在最新版本删掉，仍可能留在待推送的提交历史中。

在仓库运行：

~~~sh
# 按实际改动挑选相关套件，此处仅为示例
node --test test/history-images.test.js
npm run check
# 新增文件精确暂存后，补查所有 Git 跟踪文件（含 scripts、sidecar、Python）
node scripts/check-no-secrets.mjs --tracked
# 从任意工作目录调用脚本都可；默认检查根说明、docs 和 examples
node scripts/check-doc-links.mjs
~~~

默认只跑相关测试。先写测试计划，说明各测试对应的公开行为、核心路径、边界或错误处理；按测试金字塔安排覆盖，不为简单getter/DTO补测试，合并相似场景，避免过度mock。改动跨越多个核心模块且相关测试不足，或用户要求时，再运行包含全量测试的 `npm run verify`。

脱敏守卫是模式检查，不能代替人工复核。`--tracked` 检查当前工作区中的已跟踪文件，不含未暂存的新文件和历史提交；还须检查与目标远端分支之间的**整个待推送区间**。可通过仅在本地设置 `QQ_BOT_PRIVATE_NAMES` 补充站点私有值，切勿把这些值写回仓库。检查报告只显示文件、行号和类别，不回显命中的原文。

链接检查器检查行内链接目标文件是否存在，跳过代码和网络链接；不校验锚点或引用式链接。也可显式指定要检查的文档路径。

本地提交、安装同步、Git 推送分别记录。推送后核对远端分支提交，并更新站点交接入口，避免下一位维护者继续按“未推送”操作。

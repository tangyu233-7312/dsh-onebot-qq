# 安装、升级与卸载

目标：从零装到能在 QQ 里聊天。Windows 想更细的真机步骤看 [Windows 安装](Windows安装.md)。
协议端可换——只要实现 **OneBot v11** 都行，见 §二。

## 快速开始（5 步）

| # | 做什么 | 一句话 |
|---|---|---|
| 1 | 备齐前置 | Node ≥22、DSH `0.2.1-rc.2`～`0.3.0`、pnpm |
| 2 | 起协议端并登录 QQ | 开**正向 WS 3001** + **HTTP 3000**，记 token（若有） |
| 3 | 装插件 | `dsh plugin --profile web add github:tangyu233-7312/dsh-onebot-qq` |
| 4 | 初始化数据目录 | 包目录里 `node bin/dsh-onebot-qq.mjs init` |
| 5 | 控制台填配置 | 设置 → QQ 控制台 → 新手向导：填**主人 QQ** 与地址/token |

保存后自动连接，群里 @ 它就能聊。搞不定先看 §十。

## 一、前置组件

| 组件 | 要求 |
|---|---|
| **Node.js** | `>= 22`（`node --version`） |
| **DSH** | `>= 0.2.1-rc.2 < 0.3.0`（`dsh --version`） |
| **pnpm** | `dsh plugin add` 走 pnpm；没有就 `npm i -g pnpm` 或 `corepack enable` |
| **OneBot v11 协议端** | 任选实现，需能开正向 WS + HTTP API |
| **QQ 账号** | 建议**小号**（主号有风控风险） |

没有 DSH 时：`npm install -g @deepseek-ai/dsh`。首次 `dsh web` 会自动建 `web` profile（`$DSH_HOME/profiles/web`，`$DSH_HOME` 默认 `~/.dsh`）。

## 二、准备协议端

判断标准只有一条：能对外提供**正向 WebSocket**（消息入口，常见 3001）与 **HTTP API**（发消息/取文件/查群，常见 3000）。流程都差不多：启动协议端 → 登录 QQ → 开这两个服务 → 记 token。

### NapCat（最省事，本仓库线上在用）

自带 WebUI，登录和配置都在浏览器里点。

```bash
# Docker（Linux / NAS）
docker run -d --name napcat --restart unless-stopped \
  -p 3000:3000 -p 3001:3001 -p 6099:6099 \
  -v ~/napcat/config:/app/napcat/config \
  -v ~/napcat/qq:/app/.config/QQ \
  mlikiowa/napcat-docker:latest

# 首次要扫码：从容器里取二维码（2 分钟过期，过期重取）
docker exec napcat sh -c 'base64 -w0 /app/napcat/cache/qrcode.png' | base64 -d > qr.png
```

Windows：下 [NapCatQQ Releases](https://github.com/NapNeko/NapCatQQ/releases) 整合包，跑 `launcher.bat`。

配服务：打开 `http://<那台机器>:6099/webui/`，用 `docker logs napcat` 打印的 token 登录 → 「网络配置」加两条：

| 类型 | 端口 | 用途 |
|---|---|---|
| WebSocket **服务器**（正向 WS） | 3001 | 消息入口 |
| HTTP 服务器 | 3000 | 发消息 / 取文件 / 查群 |

token 自己设一个并记住，填进 `onebot.wsToken` / `onebot.httpToken`。

### SnowLuma

v2.x 跨平台、源码可见。**不启动 QQ**：先自己拉起 QQ，再启动它注入（WebUI 默认 5099）；**3000/3001 强制带 token**，两个都必须填。细节见其自带文档。

### ⚠️ 同一个 QQ 只能在一处登录

PC 上再跑一个会和服务器那个互相踢下线。

## 三、装插件

| 方式 | 命令 | 适用 |
|---|---|---|
| **A. 插件管理器**（推荐） | 设置里搜 `dsh-onebot-qq` → 安装 | 想点鼠标 |
| **B. 命令行** | `dsh plugin --profile web add github:tangyu233-7312/dsh-onebot-qq` | 最常见 |
| **C. 手动挂载** | 自己在 profile 的 `cordis.patch.yml` 加插件行 | 不用 bundle 机制 |

B 的其它来源：

```bash
dsh plugin --profile web add /abs/path/dsh-onebot-qq-1.0.0.tgz   # npm pack 产物
dsh plugin --profile web add link:/abs/path/dsh-onebot-qq        # 开发目录（改代码立刻生效）
```

`web` 是示例 profile，换成你实际跑机器人的那个。**装完要重启 dsh-web**（插件是 ESM，不热加载）。

> 可选：profile 里若装了全局工具插件（`dsh-ops` 等），想挡住 QQ 会话对它们的访问，可另装**上游作者**维护的 `dsh-onebot-qq-opsgate`——不是本仓库的一部分，见该仓库 README。纯聊天用不到。

## 四、首次配置

### 1. 初始化数据目录

```bash
# 在包目录执行（装完是 <profile>/node_modules/dsh-onebot-qq）
node bin/dsh-onebot-qq.mjs init
# 自定义目录：
node bin/dsh-onebot-qq.mjs init --data-dir /srv/dsh-onebot-qq
```

它会建目录 → 写 `<dataDir>/config.json`（`adminQq: 0` 待填）→ 复制示例人设与句池 → **投递内置人设「蓝色大肥鱼」**。
**不覆盖已有文件**（`--force` 只覆盖 `config.json`，且先备份）。

默认数据目录：Linux/macOS `~/.dsh/dsh-onebot-qq`，Windows `%USERPROFILE%\.dsh\dsh-onebot-qq`。
自定义 `--data-dir` 时，还要让插件读同一个目录（`DSH_QQ_DATA_DIR` 或 profile patch 的 `dataDir`）。

### 2. 启动 DSH Web，打开新手向导

`dsh web` → 浏览器进设置 → **QQ 控制台 → 新手向导**。清单逐项 ✅/❌，每项一句怎么做：

| 位置 | 填什么 |
|---|---|
| 新手向导顶部 | **主人 QQ**（必填） |
| **OneBot 连接**页 | `wsUrl` / `httpUrl` / token；填完去「运维」点**「测试 OneBot 连接」** |
| **生图**页（可选） | 协议 + API 地址 + 模型 + Key；去「运维」点「检查生图配置」验证 |

**人设不用手动建**：`init` 会投递，插件首启也会兜底投递。保存后**自动连接**，不用重启。

### 3. 等价的手动方式

直接编辑 `<dataDir>/config.json`：

```json
{
  "version": 2,
  "adminQq": 10001,
  "onebot": { "wsUrl": "ws://127.0.0.1:3001", "wsToken": "", "httpUrl": "http://127.0.0.1:3000", "httpToken": "" }
}
```

| 键 | 必填 | 说明 |
|---|---|---|
| `adminQq` | ✅ | 主人 QQ（唯一） |
| `onebot.wsUrl` / `httpUrl` | ✅ | 协议端地址 |
| `onebot.wsToken` / `httpToken` | 看实现 | SnowLuma 必填，多数实现可选 |
| `credentials.gptImage.*` | 可选 | 生图凭据；也可用环境变量 |
| `dsh.agentPreset` | 可选 | 默认 `qq-chat`（随包声明的纯聊天 preset，安装即用）；留空也会自动启用 |
| `dsh.workspaceTitle` | 可选 | QQ 工作区显示名，默认「QQ 聊天」 |
| `archive.enabled` / `dir` | 可选 | 聊天留档，默认开、写 `<dataDir>/logs/qq_chat` |

> `10001` 是占位，换成你自己的号。**手改配置要重启 dsh-web**；控制台改是热生效。

### 4. 自检

```bash
node bin/dsh-onebot-qq.mjs doctor
node bin/dsh-onebot-qq.mjs doctor --no-net   # 不起网络探测
```

有 ❌ 就退出码 1。常见 ❌：配置不存在、`adminQq` 未填、协议端 URL 未填。人设缺失只是 ⚠️，不影响聊天。

换人设：

```bash
node bin/dsh-onebot-qq.mjs persona list
node bin/dsh-onebot-qq.mjs persona use 蓝色大肥鱼
```

想写句池与唤醒词见 [使用说明书 §6](使用说明书.md#6-人设怎么写)。

## 五、验收

| 检查 | 通过标准 |
|---|---|
| 服务 | `dsh web` 正常，日志无 ERROR |
| 连接 | 日志有「OneBot WS 已连接」+ 内核就绪，或「测试 OneBot 连接」返回 ok |
| 真回话 | 私聊发一句有回复；群里 @ 它也有 |
| 能力抽检 | `/status` 能回；控制台能热改一个开关；`send_image` 能发 `<dataDir>/workspace` 里的图 |

最小判断：控制台「🧪 检查运行环境」必需项全绿 · 侧栏出现「QQ 聊天」工作区 · 私聊发一句有回复。
没有 QQ 环境时 `npm test` 就能验内核链路。

> 装完想知道「功能到底用上没」，看总览页的**功能自检**：✅ 已用上 / ⭕ 关着 / ⚠️ 开着但依赖不在，每项都写了去哪配。

## 六、升级、卸载、回滚

| 操作 | 做法 |
|---|---|
| **升级** | 插件管理器点「更新」，或 `dsh plugin --profile web remove dsh-onebot-qq` 后重新 `add`；然后重启 dsh-web。**先备份 `<dataDir>`**（配置+人设+表情库+会话状态） |
| **卸载** | `dsh plugin --profile web remove dsh-onebot-qq`。**不会删数据目录**，确认不要了再手删。手动挂过 patch 的还要删掉 `cordis.patch.yml` 里那行 |
| **回滚** | 装回旧版本即可（数据目录保留）。preset/工作区异常时，把 `dsh.agentPreset` 留空或改回 `qq-chat`，重启恢复默认装配 |

升级只换代码，数据目录与实例配置不受影响；新增键走 schema 默认值，改名的键按 CHANGELOG 处理。

从更早的包名 `dsh-qq-bot` 升级：新版默认目录是 `$DSH_HOME/dsh-onebot-qq`，但**旧目录存在时会自动沿用**，不用搬配置。

> ⚠️ 重装/升级会把 `node_modules/dsh-onebot-qq` 换成仓库版本。**改过代码的实例升级后要重新同步本地改动**。

## 七、权限与凭据

- `init` 会尽量把 `config.json` 设成 `0600`、数据目录 `0700`（Windows 上 chmod 基本无效）：

  ```powershell
  icacls "$env:USERPROFILE\.dsh\dsh-onebot-qq\config.json" /inheritance:r /grant:r "$env:USERNAME:(R,W)"
  ```

- 生图凭据优先放**环境变量**（DSH 进程环境）：`QQ_IMAGEGEN_API_KEY` / `QQ_IMAGEGEN_BASE_URL` / `QQ_IMAGEGEN_MODEL`；`credentials.gptImage` 可作后备（记得 0600）。
- 协议端 token 只放实例配置（`onebot.wsToken`/`httpToken`），**不要写进 profile patch、不要提交 git**。

## 八、极简 profile 的特殊情况

宿主完全没有 `workspaceRegistry` / `agentPresets` 服务时（只有自己拼的极简 profile），插件会自动降级（QQ 会话不归组、用默认工具面）并提示补装：

```bash
dsh plugin --profile <profile> add @deepseek-ai/dsh-workspace
dsh plugin --profile <profile> add @deepseek-ai/dsh-agent-preset-registry
```

## 九、装不上 / 起不来

先跑一键诊断（控制台 运维 → 🩺 一键诊断，生成**脱敏**报告并告诉你路径），详见 [排错](排错.md)。三个最快入口：

```bash
node bin/dsh-onebot-qq.mjs doctor      # 环境与配置
dsh --profile web --dump-config        # profile 里插件行是否挂上
curl -s http://127.0.0.1:3000          # 协议端 HTTP 通不通
```

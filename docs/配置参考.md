# 实例配置（`config.json` v2）

> 本文是**配置键的完整参考**。所有示例值都是占位（`10001`、`~/...`、`https://example.invalid`），
> 真实值填在你自己的实例配置里；**不要**把真实 QQ 号/群号/token 提交到任何仓库。

## 一、配置分几层

| 层 | 载体 | 放什么 | 谁改 |
|---|---|---|---|
| ① bundle 引导配置 | profile patch 里 `dsh-onebot-qq` 的 `config:` | `dataDir` / `configPath` / `autoConnect` / `compatServer` / `compatPort` | 安装时写一次，很少动 |
| ② **实例配置** | `<dataDir>/config.json` | 本文的全部业务键 | 手改 / 控制台热改 |
| ③ 环境变量 | `QQ_IMAGEGEN_*` | 生图凭据（覆盖 ② 的 `credentials.gptImage`） | 启动 DSH 前 export |
| ④ 数据目录 | `<dataDir>/…` | 人设、表情库、长期记忆、日志、会话状态等运行数据 | 机器人自己写 |

**位置**：

```
<dataDir> 优先级：bundle 配置 dataDir > 环境变量 DSH_QQ_DATA_DIR > $DSH_HOME/dsh-onebot-qq
<config>  = bundle 配置 configPath；留空 = <dataDir>/config.json
$DSH_HOME = 环境变量；留空 = ~/.dsh
```

> **改名兼容**：本插件原名 `dsh-qq-bot`。升级到 0.1.1 后，若新默认目录 `$DSH_HOME/dsh-onebot-qq`
> 不存在、而旧目录 `$DSH_HOME/dsh-qq-bot` 存在，会**自动继续使用旧目录**（配置、人设、表情库都不动）。
> 想换成新名字：把整个目录搬过去，或在 bundle 配置里显式写 `dataDir`。

> 自定义数据目录有两种正确做法（**只跑 `bin init --data-dir X` 不够**：init 只在 X 下写 config，
> 插件默认仍读 `$DSH_HOME/dsh-onebot-qq`）：
> 1. 启动 DSH 前设 `DSH_QQ_DATA_DIR=X`（推荐，最省事）；
> 2. 或改 profile 的 `cordis.patch.yml` 里 `dsh-onebot-qq` 行 `config.dataDir: '...'`
>    （profile patch 行的 `config` 是**整体替换**，要把 `dataDir/configPath/autoConnect/compatServer/compatPort` 写全）。

典型路径：Linux/macOS `~/.dsh/dsh-onebot-qq/config.json`；Windows `%USERPROFILE%\.dsh\dsh-onebot-qq\config.json`。

**要不要整个换位置**：可以。`dataDir` 写绝对路径即可；`configPath` 单独指到别处也支持。
相对路径（含人设/表情库等目录）**一律相对 `dataDir`** 解析，所以整个数据目录可以整体搬走。

### 控制台页面 ↔ 配置归属

| 控制台页 | 里面是什么（配置路径不变，只是归属/分组调整） |
|---|---|
| 群聊 | 核心项（主人 QQ / 入站条数上限）+ `gate-wake.enabled` + `commands.enabled` + 每群卡片 |
| 唤醒 | `gate-wake` 全部可见项（门禁与唤醒、唤醒词、必须被叫、接续窗口、关键词冷却、答应声、被戳回一句）+ `anti-repeat`（防刷屏） |
| 语气守卫 | `tone-guard` 全部可见项（判定接口 / 判定规则 / 处置 / 豁免）+ 页面顶部的**实时状态**块（没填接口时会明说「未启用」） |
| 句池 | `persona-voice` 全部可见项（句池开关、人设目录、当前人设、引用纪律） |
| 生图 | `imagegen` 全部可见项，**含生图凭据** `credentials.gptImage.*`（存储路径不变，旧配置零迁移） |
| 文件与图片 | `file-transfer` 行为类开关（总开关 / 下载时机 / 大小上限 / 数量上限 / 保留天数）+ `video-read` / `video-link-read`（看视频与视频链接，可选） |
| 其他 | 权限 / 门禁 / 文件 / 发图 / 头像 五组低频配置（原隐藏页统一并到这里，含入站目录、发图白名单、头像缓存）+ `private-friend-gate`（私聊只回好友，可选） |
| 长期记忆 | `long-memory`（固定页「记忆」） |

> 子插件页是 **13 个子插件**（9 个主功能 + 4 个可选）的启停汇总，和各自功能页里的 `enabled` 开关**同源**（改哪边都一样）。

## 二、最小可用配置

```json
{
  "version": 2,
  "adminQq": 10001,
  "onebot": {
    "wsUrl": "ws://127.0.0.1:3001",
    "wsToken": "YOUR_WS_TOKEN",
    "httpUrl": "http://127.0.0.1:3000",
    "httpToken": "YOUR_HTTP_TOKEN"
  }
}
```

除上面的必填项外，其余键不写就用默认值。完整默认值可用 `node bin/dsh-onebot-qq.mjs init` 生成一份。

> **不用先手改 JSON**：缺 `adminQq` 时插件进入「待配置模式」（控制台可用、工具已注册、不连协议端），
> 打开 设置 → QQ 控制台 →「新手向导」填主人 QQ 与协议端地址即可，保存后自动连接。
> 上面的 JSON 是手改方式（改完需重启 dsh-web）。

## 三、路径规则

- 键名以 **`dir` / `file` / `path` 结尾**的字符串 → 相对 `dataDir` 解析；
- 键名以 **`whitelist` / `roots` / `dirs` / `paths` 结尾**的字符串数组 → 逐项解析；
- 以 `~` 开头 → 相对用户主目录展开；
- 已是绝对路径（POSIX `/…`；Windows `C:\…` / `C:/…` / `\\server\share` / `file://`）→ 原样使用；
- `http(s)://` URL 不当路径处理（如 `link-parser.parserUrl`）。

> 自己加配置项时照这个命名法，路径就会被自动解析，不用改代码。

## 四、核心键

### `version` / `adminQq`

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `version` | int | `2` | 配置格式版本；当前只有 v2 |
| `adminQq` | int | `0` | **必填**。主人 QQ 号（唯一）。`0`/缺失 → 启动时报错；出口脱敏只有对主人私聊豁免 |

### `onebot`

**协议端连接配置**。**键名是 `onebot.*`，可对接任意 OneBot v11 协议端**；旧版配置里的 `napcat.*` 仍能读（自动兼容），接 SnowLuma 也用这一段。

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `wsUrl` | str | `ws://127.0.0.1:3001` | OneBot v11 **正向 WebSocket** 地址（收消息） |
| `wsToken` | str | `""` | WS 鉴权 token。协议端开了鉴权才填（多数实现可选）；**SnowLuma 必填**（它强制生成 accessToken） |
| `httpUrl` | str | `http://127.0.0.1:3000` | OneBot **HTTP API** 地址（发消息/取文件/查群） |
| `httpToken` | str | `""` | HTTP 鉴权 token。同上：SnowLuma 必填 |

> **不同实现的差别**：多数实现的 token 可以留空（裸跑）；SnowLuma 的 3000/3001 **强制带 `accessToken`**
> （每个网络自动生成 32 字节 base64url，在它 WebUI 或 `config/onebot.json` 里看），所以要分别填 `wsToken`/`httpToken`。
> 端口的常见默认值基本一致，换协议端通常**只改 token**、不用改地址。

### `dsh`

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `agentPreset` | str | `"qq-chat"` | 给 QQ 线用的 agent preset 名。**内置 `qq-chat` 随包声明**（纯聊天 + 联网，裁掉 shell / 文件 / 任务 / 技能 / 插件管理类工具），留空时插件自动启用；填别的名字 = 用你自己的 preset；该 preset 不存在时回退 DSH 默认工具面 |
| `qqWorkspacePath` | path | `"workspace"` | QQ 线的会话工作目录（`AGENTS.md` / `CLAUDE.local.md` / 人设投递文件在这里）；插件启动时把这个目录注册成 DSH 工作区 |
| `workspaceTitle` | str | `"QQ 聊天"` | QQ 工作区在 DSH 侧栏的显示名。启动/保存配置时按路径创建（或复用），同路径只复用不重复创建 |
| `sessionsFile` | path | `"state/sessions.json"` | chatKey → DSH sessionId 映射（重启后能续聊） |

### `outbound`

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `replyMaxLength` | int | `3000` | 单条回复最大长度（超出截断/分段） |
| `longForwardThreshold` | int | `400` | 超过多少字改用「合并转发卡片」；带 @/引用的长文不套卡片 |
| `longForwardChunkSize` | int | `800` | 卡片里每段节点的长度 |
| `quoteAfterMsgs` | int | `3` | 回复发出前同群插了几条才自动挂引用；`0` = 关掉自动引用 |
| `groupContextCount` | int | `10` | **入站条数上限**：每轮最多带几条"还没看过的"群消息（只取上次回复后新增、30 分钟内）；超过就只给最后 N 条，更早的丢弃不补。每条约 20 token；`0` = 不带上文 |

### `archive`

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 是否把进出消息写成 JSONL 留档 |
| `dir` | path | `"logs/qq_chat"` | 留档目录（每个会话一个 `<kind>_<id>.jsonl`） |

### `toolPrefix` / `plugins`

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `toolPrefix` | str | `"mcp__qq__"` | 原生工具名前缀（改它会影响人设/指令里的工具名，谨慎） |
| `plugins` | object | `{}` | 子插件**硬开关**：`{"stickers": false}` = 这一轮完全不加载该插件 |

### `pacing`（回复节奏）

`pacing.merge.*`：同一会话多条消息的合批。

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 是否合批 |
| `windowMs` | int | `2000` | 首条消息后的合批窗口 |
| `maxWaitMs` | int | `6000` | 最长等待 |
| `skipIfSlowMs` | int | `30000` | 模型慢于该值时跳过后续合批 |
| `windowActiveMs` | int | `4000` | 正在回复时的合批窗口 |
| `activeGapMs` | int | `15000` | 判定「正在聊」的间隔 |

`pacing.reply.*`：主动接话（没人叫也可能自然插话）。

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `false` | 总开关 |
| `hourlyMax` | int | `6` | 每小时最多主动接话次数 |
| `minGapMs` | int | `480000` | 两次主动接话最小间隔（毫秒） |
| `silenceEnabled` | bool | `true` | 冷场找话；`false` = 只在群里有新消息时才可能接话（不再定时找话） |
| `coldSilenceMs` | int | `180000` | 群冷场多久后允许接话（仅 `silenceEnabled=true` 时生效） |
| `topicWindowMs` | int | `600000` | 话题统计窗口 |
| `topicMinMsgs` | int | `3` | 窗口内至少几条消息才算有话题 |
| `sensitivity` | float | `0.45` | 接话倾向（0–1，越大越爱接） |
| `maxChars` | int | `140` | 主动接话字数上限 |
| `groups` | array | `[]` | 允许主动接话的群号；`[]` = 不主动接话 |
| `style.splitEnabled` | bool | `true` | 是否拆条 |
| `style.splitProbability` | float | `0.5` | 拆条概率（0–1） |
| `style.splitMinLen` | int | `12` | 短于该长度不拆 |
| `style.splitDelayMs` | int | `1000` | 拆条间隔（毫秒；第 N 条等 N×间隔） |
| `style.splitMaxParts` | int | `3` | 一段回复最多拆几条（2–4）。只在句末标点/换行处拆，长文（>120 字）不拆、交给长文卡片 |
| `style.stickerEnabled` | bool | `true` | 主动接话时是否可能带表情包 |
| `style.stickerProbability` | float | `0.8` | 带表情包概率（0–1） |
| `continuation.enabled` | bool | `false` | 连续对话总开关（控制台「主动接话 → 连续对话（展开）」里的第一项） |
| `continuation.delayMs` | int | `120000` | 从"回复真的发出"起等多久检查（毫秒） |
| `continuation.bonus` | float | `1.5` | 情境加分：复用上面的 `weights` 算出 logit，再加这个值换算成"续聊分" |
| `continuation.hourlyMax` | int | `5` | 每群每小时最多补几次 |
| `continuation.minGapMs` | int | `300000` | 两次续聊最小间隔（毫秒，默认 5 分钟） |
| `continuation.maxPerChain` | int | `1` | 一次唤醒最多检查几次（防自转核心，建议保持 1） |
| `continuation.requireNewMessage` | bool | `true` | 必须有人类新消息才检查（关掉容易变成自问自答） |
| `continuation.quoteLastHuman` | bool | `false` | 续聊时是否引用最后一条人类消息 |

> 控制台里这 8 项收在「主动接话」页的 **「连续对话」折叠块**里（默认收起，点开才显示），不和常用项平铺竞争版面。
| `weights.*` | float | 见下 | 接话打分特征权重，一般不用动 |

`pacing.reply.weights` 默认值：
`intercept -1.2005`、`mentionBot 1.5852`、`atOther -1.1157`、`hasQuestion 0.4807`、
`placeholderOnly -1.0281`、`selfRatio 2.6525`、`recentCount -0.0367`、
`logSecondsSinceBot 0.0571`、`pendingCount 0.1012`。

> 一般只改 `enabled` / `groups` / `hourlyMax` / `sensitivity`；权重是调参细节。
>
> **拆条/表情概率的权威值在 `pacing.reply.style`**：内核每次配置重载会把
> `persona-voice.splitReply*` 与 `stickers.offerPercent` 同步成这里的值（控制台「主动接话」页改这里）。

### `credentials`

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `gptImage.protocol` | enum | `"openai-images"` | 生图协议：`openai-images`（`/images/generations` + `/images/edits`）或 `openai-chat`（`/chat/completions`，部分中转站/模型用对话接口出图） |
| `gptImage.baseUrl` | str | `""` | 生图 API 基址（OpenAI 兼容），如 `https://example.invalid/v1` |
| `gptImage.apiKey` | str | `""` | **不要写进仓库**；建议用环境变量 `QQ_IMAGEGEN_API_KEY` |
| `gptImage.model` | str | `"gpt-image-2"` | 生图模型名（以你的中转/服务为准） |

环境变量优先级（**覆盖**实例配置/控制台输入框，`loadConfig` 时就生效）：

| 环境变量 | 覆盖字段 |
|---|---|
| `QQ_IMAGEGEN_PROTOCOL` | `credentials.gptImage.protocol` |
| `QQ_IMAGEGEN_BASE_URL` | `credentials.gptImage.baseUrl` |
| `QQ_IMAGEGEN_API_KEY` | `credentials.gptImage.apiKey` |
| `QQ_IMAGEGEN_MODEL` | `credentials.gptImage.model` |

> 协议选哪个：**默认先试 `openai-images`**；如果中转站/模型只支持对话接口出图（返回 chat 响应），再切
> `openai-chat`。控制台「运维」页有「检查生图配置」按钮可验证地址/Key/模型是否可用。

#### 语气守卫的判定接口（`credentials.toneGuard`，2026-11-08）

「语气守卫」判断辱骂 / 垃圾消息要单独调一次模型。默认要求自己填一条 OpenAI 兼容接口（在控制台「语气守卫」页填）：

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `toneGuard.baseUrl` | str | `""` | OpenAI 兼容的 `/v1` 基址，如 `https://example.invalid/v1`。本机模型填 `http://127.0.0.1:11434/v1` 就是零成本判定 |
| `toneGuard.model` | str | `""` | 判定用的模型名（以你的中转站为准；flash / mini 档够用） |
| `toneGuard.apiKey` | str | `""` | **不要写进仓库**；控制台只回显掩码，写回掩码 = 不改。本机服务可留空 |

> `baseUrl` 与 `model` **都填了**才算就绪；缺任何一个 = 整个语气守卫不启用（不判定、不记账、不改语气），
> 机器人行为与装它之前完全一样。控制台「总览」新手向导与「语气守卫」页会写明缺什么。
> 这组**没有环境变量覆盖**（故意的：可选能力配在控制台就够，少一条隐式来源少一处「为什么没生效」）。
> 想省掉这次调用又不想填接口：把 `judgeSource` 切成 `host`，判定走宿主默认模型。

#### 多级降级：第 3 / 第 4 级备用接口（2026-11-07）

生图共四级来源，**按顺序用，前面的能用就不碰后面的**：

| 级 | 来源 | 什么时候用 |
|---|---|---|
| 第 1 级 | 本机 ComfyUI（`localFirst`） | 探活通过时 |
| 第 2 级 | 主站（`credentials.gptImage`） | 本机没起 / 没开本机 |
| 第 3 级 | 备用接口 1 | 主站失败时 |
| 第 4 级 | 备用接口 2 | 第 3 级也失败时 |

控制台「生图」页底部有两个可折叠小节 **「备用接口 1」「备用接口 2」**，点开后的字段和主站一模一样：

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `fallback1BaseUrl` / `fallback2BaseUrl` | str | `""` | 该级 API 地址（填到 `/v1`）。**留空 = 这一级不用** |
| `fallback1Protocol` / `fallback2Protocol` | enum | `""` | 留空跟随主站；也可单独选 `openai-images` / `openai-chat` |
| `fallback1Model` / `fallback2Model` | str | `""` | 留空跟随主站模型 |
| `fallback1ApiKey` / `fallback2ApiKey` | str | `""` | 面板脱敏；留空 = 不修改。也可改用环境变量 `QQ_IMAGEGEN_KEY_3` / `QQ_IMAGEGEN_KEY_4`（配了优先） |

降级规则（重要）：

- **顺序降级，不是轮询**：主站能出图就只用主站（画风稳定、不额外花钱）；只有失败才往下走。
- 每级**只打一次**，绝不重试同一级；某一级成功立刻停。
- `400 / 422` **不降级**（请求本身不合法，换站也一样，只会多打一次）；其余错误（超时 / 连不上 / 5xx / 401 / 429 / 没出图）才降级。
- 总超时按**剩余级数均分**（单级至少 15 秒），避免第一级卡死把后面全饿死。
- ⚠️ **超时也会降级**：对方可能其实已经出图了，极端情况下会多计一次费。
- 本地（第 1 级）出图**失败不回落**中转站 —— 与旧规则一致（防重复计费）；只有本地**没起来**才走第 2 级。
- 全部失败时错误里汇总每一级的原因；用户只会收到**一句**失败话术，不会按级刷屏。
- 回执新增 `tier`（实际生效的级）与 `fallbackUsed`（是否用了备用），日志里也会写「第 N 级」。
- 地址写错会**立刻报错**（不占冷却、不先说「在画了」），不会静默跳过你以为配好的那一级。

检查方式：控制台「运维」页「🖼 检查生图配置」会多出一行「备用接口」，只校验地址是否合法，不会真把所有站打一遍。

#### 本机画图服务（`pluginConfig.imagegen.local*`，2026-11-07）

PC 上如果自己部署了 ComfyUI（**官方本体即可，无需包装服务**），可以让它**优先出图**（免费、约 11~30 秒），
服务没起来时**自动回落**中转站。NAS 没有 GPU，保持 `localFirst: false` 即可 —— 那时**一次都不会去探本地**。

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `localFirst` | bool | `false` | 开：每次生图先探一次本机服务（≤2.5 秒）；活着走本地，没起来回落中转站 |
| `localAdapter` | enum | `native` | `native` = **官方 ComfyUI 本体**（8188 那套原生 API）；`simple-api` = 带 `/api/generate` 的自建包装服务（旧配置兼容） |
| `localUrl` | str | `""` | 本机服务地址，插件不预设端口。官方 ComfyUI 通常是 `http://127.0.0.1:8188` |
| `localWorkflow` | text | `""` | **仅 native**：ComfyUI **Save (API Format)** 导出的工作流 JSON，占位符见下 |
| `localModel` | str | `""` | **仅 simple-api**：那套服务里的模型标识，由你填；native 模式下不生效（模型写在工作流里） |
| `localDenoise` | float | `0.65` | 图生图降噪强度（0.2~1.0），替换进 `{{denoise}}` |

**native 模式怎么配**（推荐，装了官方 ComfyUI 就能用）：

1. 在 ComfyUI 里把工作流搭好 —— 模型、LoRA、采样器、步数都在工作流里定，**插件不猜也不改**；
2. 把要由机器人填的值改成占位符：正向提示词 `{{prompt}}`（**必填**），可选 `{{negative}}`、`{{width}}`、`{{height}}`、`{{seed}}`；
   图生图再在链路里加一个 LoadImage 节点，其 image 值写 `{{image}}`，降噪写 `{{denoise}}`；
3. 菜单 **Save (API Format)** 导出（注意不是普通 Save，那个不是纯 API 格式），把 JSON 整段贴进 `localWorkflow`。

链路：探活 `GET /system_stats` → 提交 `POST /prompt` → 轮询 `GET /history/<id>` → 取图 `GET /view`；
图生图先 `POST /upload/image` 传底图。「🔍 读取本机可用模型」在 native 模式下读 `GET /object_info/*`
（checkpoint / unet / vae 清单），结果仅供填工作流参考 —— 真正用什么模型以工作流为准。

> **为什么模型不写死**：每套 ComfyUI 装的模型都不一样（`z_image_turbo`、`sd_xl_base`、`flux1-dev`、
> 自己 merge 的…）。native 模式把模型选择完全留在工作流里；simple-api 模式由服务自己报清单。
> 插件里**一个模型名都不出现**。

> **防呆**：模板缺 `{{prompt}}`、图生图请求但模板缺 `{{image}}`、贴了非 API Format 的 JSON、
> ComfyUI 节点报错 —— 都**明确报错**，不会静默出一张无关的图。

**simple-api 模式**（旧配置兼容）：目标服务需提供 `POST /api/generate`（回 `prompt_id`）、
`GET /api/progress/<id>`、`GET /image/<name>`，可选 `GET /api/status`（探活 + 模型清单）。

行为约定：

- 本地可用 → 走本地，**不要求中转站 API Key**；
- 本地不可用 → 回落中转站；两边都没配才报「未配置生图凭据」（并在括号里说明本地也不可用）；
- **不会自动拉起**本地服务（静默加载 6GB 权重太粗暴），需要手动启动；
- 一次生图只画一次：本地失败**不**偷偷改走中转站（防重复计费）；
- `generate_image` 的返回值里 `source` = `local` / `remote`，`protocol` 在本地时是 `comfyui`。

### `tone-guard`（order 17，语气守卫）

用**模型**判断对方是不是在辱骂 / 发垃圾消息 —— 不是关键词表：「笨鱼」「傻鱼」「傻子」「笨蛋」是调侃，
「傻逼」「有病吧你」才是骂；同一个词换个语气意思就变，只能看语境。判出来之后按**确定的状态机**处置：

| 情形 | 处置 |
|---|---|
| 辱骂 第 1、2 次 | **什么都不加**：照常按人设回话，prompt 里一个字符都没有（模型察觉不到被记账） |
| 辱骂累计到第 `strikeLimit` 次 | 进**攻击态** `attackMin` 分钟：把 `attackPrompt` 压进 prompt，只怼这个人 |
| 攻击态期间 | 他每说一句都照样怼（再骂会重新计时）；到点自动回人设 |
| 垃圾消息 第 1 次 | 不回（0 token），记一条 |
| 垃圾消息**连续**第 2 次 | 屏蔽 `spamMuteMin` 分钟：期间他的消息在 pre-gate 就被拦下，不判定、不进模型 |

判定只发生在**被唤醒的那种消息**上（`@` / 关键词 / 引用 / 私聊）。主动接话、续聊检查、入群欢迎都是它自己起念，一律不判。
主人永久豁免。判定失败（超时 / 坏 JSON / 接口报错）一律 **fail-open**：这条不判，照常回话。

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 插件总开关（关 = 完全不碰） |
| `judgeSource` | enum | `"custom"` | `custom` = 用你填的接口（没填就不启用）；`host` = 用宿主默认模型（不用填 Key，但每轮多一次主模型调用） |
| `extraBody` | text(JSON) | `""` | 并进判定请求体，处理各家差异（如 `{"enable_thinking": false}`）；非法 JSON 只记日志、忽略 |
| `timeoutMs` | int(秒) | `6` | 判定超时；超了当没判（这是每轮多等的最坏时间） |
| `maxTokens` | int | `64` | 判定输出上限（只要一行 JSON） |
| `judgePrompt` | text | 内置规则 | **判定规则**，控制台可整段改；末尾的输出格式由插件自动接上 |
| `contextCount` | int | `2` | 连带最近几条同会话消息给判定看（分清打情骂俏和真挑衅），每条截 120 字 |
| `minConfidence` | float | `0.7` | 模型的 confidence 低于它一律当没判（宁可漏判） |
| `strikeLimit` | int | `3` | 几次辱骂开始开怼 |
| `windowMin` | int(分钟) | `60` | 辱骂计数窗口（**按累计**，中间说正常话不重置）；垃圾消息的「连续」也用它判 |
| `attackMin` | int(分钟) | `15` | 攻击态持续多久 |
| `attackPrompt` | text | 内置指令 | 攻击态压进 prompt 的那段；占位符 `{name}` `{qq}` `{count}` `{until}` `{left}` |
| `spamStreakLimit` | int | `2` | 连续几条垃圾消息开始屏蔽 |
| `spamMuteMin` | int(分钟) | `15` | 屏蔽时长 |
| `spamSilent` | bool | `true` | 判出垃圾消息直接不回；关 = 只记账、仍然回话（想先观察几天再开用它） |
| `exemptQqs` | array | `[]` | 这些号不判定（主人本来就豁免） |
| `exemptGroups` | array | `[]` | 这些群完全不判 |

落盘状态在 `<dataDir>/tone-guard.json`（次数 / 攻击态 / 屏蔽到期），跨重启有效。
主人命令：`/tone status`（谁被记账）、`/tone test <一句话>`（试判一条，花一次判定调用）、`/tone clear [QQ|all]`。

### `qzone`（order 62，QQ 空间日记）

> 2026-10-30 起：到点**只提醒、不自动写**。`nudgeHour`/`nudgeMinute` 是第一次提醒（默认 22:30），`nudgeMinute2` 是隔多久再问一次（默认 30 分钟 → 23:00），`nudgeTo` 填 `private:<主人QQ>` 才真的推；两次问完不再打扰。

给机器人一个自己的 QQ 空间当日记本：每个会话每天最多一条，由它自己决定写不写。

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 插件总开关（关掉 = 不提醒、工具不可用） |
| `dailyLimit` | int | `1` | 每个会话每天最多发几条（建议保持 1：有选择压力才不会写成流水账） |
| `remindAfterHour` | int | `22` | 每天几点后提醒它考虑（24 小时制；`0` = 不提醒） |
| `maxChars` | int | `300` | 单条正文上限（超出截断，不报错） |
| `maxImages` | int | `1` | 最多配几张图（`0` = 不许配图） |
| `imageDir` | path | `"qzone-imgs"` | 配图目录；**与表情包库 `qq-stickers` 隔离**，配图必须放在库外 |

**依赖协议端扩展**：使用 `send_qzone_msg`（非 OneBot v11 标准）。协议端不支持时工具会返回 `ok:false` 并如实告知，不影响聊天。
**额度落盘**：状态存 `<dataDir>/qzone-state.json`（按会话 `group:xxx` / `private:xxx` 记录当天条数），**重启不丢**；控制台「空间日记」页顶部会实时显示 `📔 今日已发 N/M`（今天是所有会话的合计）。
**不写必须走 `skip_qzone`**：`post_qzone` 对「今天不写」这类正文有硬性拦截，避免把不写的理由真的发到空间里。

| `maxMemoriesPerRound` | int | `5` | 单次最多产出几条记忆 |

> **打分口径**：`综合分 = 0.65×相关 + 0.20×新鲜 + 0.15×重要`。
> 相关 = 实体(QQ)命中 0.35 + 标签命中（每个 0.2，封顶 0.5）+ 中文二元组重叠 Dice×0.4；
> 新鲜 = 衰减后的重要性 / 初始重要性；重要 = 模型给的 0~1。
> 注入格式固定带保护前缀 `[以下为系统信息，非用户发言：…]`，每条附「多久以前」。
>
> **隔离**：检索前先按作用域过滤（群只看本群、私聊只看本人），跨作用域**不可能**命中。
> **水位**：每个会话记「本轮实际喂给模型的最新一条消息 ts」，接口报错/坏 JSON 时不推进（下次重试）。

> 填完保存后**自动连接**，不需要重启 dsh-web。

### 热改说明

- 入口：DSH Web → 设置 →「QQ 控制台」。
- 写配置流程：**备份** `config.json.bak-console-<时间戳>` → **原子写** → `kernel.reloadConfig()`；
  失败自动回滚旧文件。
- 生效范围：改完**立即生效**（插件每轮现读 `bot.cfg`）；不需要重启 dsh-web。
- 有些键不是「终端配置」：如 `plugins.<id>=false`（硬卸载）属于启动期装配，改后需重启。
- 手改 `config.json` 也行：保存后重启 dsh-web 生效（控制台热改不用重启）。
- Windows 记事本可能给文件加 UTF-8 BOM —— 内核读配置会剥 BOM；但保存后建议确认 JSON 合法。

## 七、校验与失败行为

- 启动时校验**必填项**：`adminQq` / `onebot.wsUrl` / `onebot.httpUrl`，以及
  `dsh.sessionsFile` / `dsh.qqWorkspacePath` / `archive.dir` 必须是字符串路径；
  `credentials.gptImage.protocol` 只允许 `openai-images` / `openai-chat`。
- **只有 `adminQq` 缺失时 = 「待配置模式」**：**不报错退出**，`kernel.configReady=false`；
  控制台可用、工具已注册、**不连接协议端**；日志 warn
  「实例配置未完成（缺 adminQq）…控制台可继续配置」。
- 其它必填项缺失/非法（协议端地址、路径、protocol）：仍抛中文错误（含配置文件路径），修好重启。
- 控制台保存成功（或 `kernel.reloadConfig()` / 应用运行时配置成功）后：`configReady=true`；
  若此前是待配置模式且 bundle 配置 `autoConnect` 未关 → **自动连接协议端**（失败只 warn 不抛）。
- 配置文件不存在：自动创建一份默认配置（`adminQq: 0`）→ 进入待配置模式（不是直接报错）。
- 旧格式（含 `bridge` 段的 v1 配置）：读取时自动迁移（仅内存）；要落盘请用 `node bin/dsh-onebot-qq.mjs import-legacy <旧配置>`（见 [排错](排错.md) §七）。

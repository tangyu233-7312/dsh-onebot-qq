# QQ 机器人使用说明书

> 一句话：装好 DSH 插件 → 连上协议端（OneBot v11）→ 填主人 QQ → 在 QQ 里 @ 它就能用。
> 只想跑通看 1~3 节；功能怎么用看 4~5 节；人设怎么写看第 6 节；出问题看第 7 节。
> 📖 **文档入口**：[功能手册总览](README.md)。本文只讲「怎么用」；安装/升级/卸载看[安装与卸载](安装与卸载.md)，Windows 看[Windows 安装](Windows安装.md)，配置键看[配置参考](配置参考.md)，故障看[排错](排错.md)。

---

## 1. 准备什么

| 东西 | 要求 |
|---|---|
| **DSH**（DeepSeek Harness） | `>= 0.2.1-rc.2 < 0.3.0`，桌面版或 `dsh web` 都行 |
| **OneBot v11 协议端** | 任意实现（如 SnowLuma、OneBot 等）；需要开 **正向 WebSocket**（常见默认 3001）和 **HTTP API**（常见默认 3000） |
| **SnowLuma**（可选，本机在用） | v2.2.0，OneBot v11 实现（默认端口同 3001/3000）；**不启动 QQ**，注入已运行的 QQ 进程，且两个端口**强制 token**。接法见 §3 |
| **一个 QQ 号** | 建议用小号；协议端登录它，机器人用它收发消息 |

> 三样都在同一台电脑上最省事；协议端装在别的机器也行，地址填通即可。

## 2. 安装（最短路径）

```bash
dsh plugin --profile web add github:YUsaltyfish/dsh-onebot-qq   # ① 装插件
node bin/dsh-onebot-qq.mjs init                                # ② 建数据目录 + 默认人设（包目录执行）
dsh web                                                        # ③ 启动
```

> 数据目录默认 `~/.dsh/dsh-onebot-qq`（Windows：`%USERPROFILE%\.dsh\dsh-onebot-qq`）；包目录 = 源码仓库根或安装后的 `<profile>/node_modules/dsh-onebot-qq`。
> 装完验收：控制台「运维 → 一键诊断」无红叉。完整安装 / 首次配置 / 升级 / 卸载 / 回滚 → [安装与卸载](安装与卸载.md)；Windows → [Windows 安装](Windows安装.md)。

## 3. 连上 QQ（协议端：OneBot v11）

1. **协议端里**：开启**正向 WebSocket**（默认 `ws://127.0.0.1:3001`）与 **HTTP API**（默认 `http://127.0.0.1:3000`），有 token 记下来。
   - **通用**：在协议端自己的界面里登录 QQ（扫码/密码都行；本插件不代登录）。
   - **SnowLuma**：**不启动 QQ** —— 先自己开 QQ 用手机扫码登录，再启动 SnowLuma 让它注入（WebUI <http://127.0.0.1:5099>，初始账号 `admin`，密码在**全新数据目录首启日志里打印一次**）；OneBot 开 WS `3001` + HTTP `3000`，**两个端口都强制 `accessToken`**，抄下来填插件。
2. **插件里**：控制台「OneBot 连接」页填 WS / HTTP 地址（+ token）→「测试 OneBot 连接」；「群聊」页填**主人 QQ** → 保存自动连接（**任意 OneBot v11 协议端都填这里**；配置键是 `onebot.*`）。
3. **验收只看两排字**：内核 已连接 + QQ 已登录（断开/未登录先看协议端 WebUI，再点「运维 → 一键诊断」）。

> **和多数实现差在哪**（接 SnowLuma 前先看）：

| 差别 | 多数实现 | SnowLuma |
|---|---|---|
| 开 QQ | 协议端自带/拉起 QQ 客户端（注入方式各实现不同） | **不启动 QQ**：先手动开 QQ 登录，再注入运行中的进程（Linux 要 `cap_sys_ptrace` 或 root） |
| token | 可选 | **3000/3001 强制** `accessToken`，`wsToken` / `httpToken` 都要填 |
| 扫码 | 协议端自带 WebUI 扫码（端口见各实现文档） | 纯扫码，**没有 CLI / 二维码 API**：无头机器用 VNC/noVNC，或截图 QQ 登录窗口发布成网页二维码 |
| 掉线判定 | WebUI 看 QQ 在线 | `get_status` 的 `good=false` = 收发链路停滞（发得出收不进） |

> 接 SnowLuma 建议关掉它自带的 `#sl` 状态指令（`statusCommand.enabled=false`）：默认开时群里发 `#sl` 框架会回一句，`swallow:false` 时还会把消息继续下发给机器人（各回一句）。另：`message_id` 是**非零有符号 int32（负值合法）**，引用/撤回用返回的真实 id；`get_file` 只覆盖图片/语音缓存，群文件/视频溯源可能降级。

## 4. 控制台一页一览

| 页面 | 干什么 |
|---|---|
| **总览** | 健康状态、新手引导、当前人设（点一下换人设） |
| **运维** | 测试连接、重连、自检、一键诊断、清理临时文件 |
| **群聊** | 主人 QQ、上文条数、基础命令开关；每个群的屏蔽/白名单/黑名单/主动接话/入群欢迎 |
| **OneBot 连接** | WS/HTTP 地址与 token、连接状态、测试按钮（任意 OneBot v11 协议端都填这里） |
| **消息设置** | 单条字数、长文卡片、引用规则、合批（连发几条并成一轮） |
| **主动接话** | 没人叫也偶尔接一句：频率、冷场判定、语境权重、拆条与表情概率 |
| **唤醒** | 门禁与唤醒总开关、免@唤醒词（填空+添加）、必须被叫、接续窗口、关键词冷却、被戳回一句 |
| **文件与图片** | 收文件总开关、什么时候下载、大小上限、单条数量上限、保留天数 |
| **句池** | 人设句池开关、人设目录、当前人设、引用纪律 |
| **入群欢迎** | 欢迎语（固定句池 / 模型现写）、图片池、延迟、测试发送 |
| **生图** | 生图凭据（协议 / 地址 / 模型 / API Key）+ 冷却、超时、参考图目录 |
| **链接解析** | B 站/抖音等链接解析（可选，用本仓库自带的 `sidecar/`，默认关） |
| **表情包** | 群表情自动收集、库上限、发表情概率与每轮上限 |
| **其他** | 低频配置：权限（主人 QQ）、门禁（屏蔽群/名单）、文件目录、发图白名单、头像缓存 |
| **子插件** | 13 个子插件的总开关（和功能页里的开关同源，改哪边都一样） |
| **群记忆** | 每个群一篇 Markdown 记忆，可看/改（自动备份旧版） |

## 5. 日常怎么用

### 5.1 叫醒它

- **群里**：必须被叫才理 —— @ 它、引用它的消息、叫到唤醒词（默认「大肥鱼」）、或刚聊完的接续窗口内补一句话。
- **私聊**：永远算被叫。
- 唤醒词在「**唤醒**」页维护（输入框 + 添加按钮，点 × 删）；**人设文件自带的词也生效**（删它会改人设文件，控制台会提示）。

### 5.2 聊天 / 发图 / 长文

- 直接说话即可；太长会自动分段或打成一张合并转发卡片（「消息设置」页调阈值）。
- 让它发本地图片：图片放到**数据目录或系统临时目录**（白名单在「其他」页），然后叫它发。只发图，**不能发文件**（QQ 侧限制）。

### 5.3 收文件

- 默认 **「被叫到时才下」**：群里没人叫它的文件不落盘，不占磁盘。想全收就在「文件与图片」页改成「过门禁的消息都下」。
- 限制：单个文件默认 **20MB**、单条消息最多 **5 个**、落盘文件保留 **7 天**后启动时自动清理。
- 落盘目录在「其他」页「文件」组；收到的文件路径会写进它的提示里。
- 注意：QQ 线是纯聊天 preset（没有文件/终端工具），它知道文件在哪但默认读不了文件内容；需要读内容要另配工具或让它把文件发到别处处理。

### 5.4 生图 / 图生图

1. 「**生图**」页填 **协议 / API 地址（到 /v1）/ 模型 / API Key**（也可用环境变量 `QQ_IMAGEGEN_*`，环境变量优先）。
2. 协议怎么选：中转站支持 `/images/generations` → 选 **OpenAI 兼容 /images/***；只给 chat 出图 → 选 **OpenAI 兼容 chat/completions**。
3. 用法：直接说「画一只…」；改图就发图/引用图再说「改成…」。
4. 规则：全局冷却默认 60 秒；失败它会自己说一句就结束（**不会自动重试**，避免重复扣费）；「在画了」同一会话 30 秒内只说一次。

> **额外请求字段**：不同平台的生图接口参数不一样（比如 sensenova／商汤默认给图加水印、要关得传 `watermark: false`；有的中转站还有 `quality`／`style`）。控制台「生图」页的「额外请求字段（JSON）」就是给这个用的：填 `{"watermark": false}` 关水印，填 `{"quality": "hd"}` 等等都行；留空 = 什么都不加。写错 JSON 会直接报错、不会把图发出去。

**本机图片怎么找**：QQ 线没有文件工具，它看不到本机目录。要它用本机的图（角色参考图、之前生成的图、群友发来的图）当参考时，它自己会先调 `list_images` 查清单（角色参考图 / QQ 工作区 / QQ 发来的文件 / 头像缓存，带尺寸），再挑一张传给 `generate_image`。你也可以直接说文件名。

### 5.5 头像

让它「看看/用某某的头像画…」——它会按 QQ 号取公开头像缓存到数据目录（缓存时长在「其他」页「头像」组），直接当图生图参考图用。

### 5.6 表情包

**默认是「只读」**：库开着、能挑图发，但**不收新图、不写索引**（「收表情（会写索引）」开关默认关）。

要用采集就打开「表情包 → 收表情（会写索引）」：开了才会把群里的新表情收进库、更新 `index.json`、记录使用次数。控制台「表情包」页顶部会显示当前库有多少张、多少张带标签。

⚠️ 索引是插件内存里的副本，**运行中直接改 `index.json` 会被写回覆盖**（2026-10-20 标签全丢就是这么来的）。要换实例/搬数据目录/改库，顺序只有一个：**停 `dsh-web` → 搬或改 → 再启动**。不需要采集时就保持这个开关关着。

采集规则：哈希去重、默认跳过 GIF、单张 1KB~2MB、上限 200 张（满了跳过新图）；回话时按概率提醒它「顺手带一张」，一轮最多 1 张。

提醒出现后它会把 `sticker:"关键词"` 直接塞进「发正文」那次工具调用里（比单独调一次 `send_sticker` 省一步，实际发出率明显更高）；如果这一轮它还是忘了，工具的返回里会再轻推一次（最多两次）。

### 5.7 入群欢迎

1. 「**群聊**」页每张群卡片勾「允许入群欢迎」（或在「入群欢迎」页填群号；填 `*` = 所有群）。
2. 「**入群欢迎**」页写欢迎语：固定句池（零 token）或模型现写；可放图片池、调延迟/冷却，点「测试发送」预览。

### 5.8 群记忆

每群一篇 `<数据目录>/qq-memory/<群号>.md`；控制台「群记忆」页能看、能改（保存前自动备份旧版，并按当前「保留多少历史版本」清理）。**自动积累是插件自带的**（默认开、每 8 小时一轮）：一轮把所有有新消息的群**合成一次模型调用**，只提炼「新增要点」写回（不是每个群各调一次）；原始聊天记录按「保留天数（默认 3 天）」**车轮式清理**，只删已消化的旧记录。更新频率 / 积累方式 / 保留天数都在控制台「群记忆」页调，键名见[配置参考 §五](配置参考.md#group-memoryorder-90群记忆)。

注意两点：① 「关掉群记忆」只停**读取**（不再注入指针），**自动积累仍在跑**，要停积累请关「自动积累群记忆」；② 每群每轮只取最近 N 条，超出部分按采样跳过，结果行会写「采样跳过 X 条」——想要更高覆盖率就调大「每群最多取多少条」或缩短间隔。手改保存如果期间积累器刚写过，会提示「已被更新」，点「刷新」看清再保存即可（避免旧内容覆盖新要点）。

### 5.9 链接解析（可选）

默认关。要开先把本仓库自带的侧车跑起来（`sidecar/start.bat`，默认监听 `127.0.0.1:3972`），
然后在「链接解析」页填地址并打开开关。见 [README 的「解析侧车」一节](../README.md#解析侧车仓库自带不自动启动)。
> 侧车要实现什么接口（`POST /parse` 的请求/响应格式）、需要装 ffmpeg 与下载器等，见仓库 README 的「可选：解析侧车」一节。

- 链接一出现就解析，**不用 @**；发媒体之外，如果这条同时还在跟它说话，会继续交给模型回一句。
- **视频类会拆条发**：QQ 客户端把视频当独立消息，所以视频单独一条、说明文字（标题/作者/时长）另起一条；图文/图集仍是「说明 + 图片」一条。这是协议端的硬限制（SnowLuma 等严格实现会直接拒绝混发）。
- 失败一律降级：侧车没起 / 超时 / 媒体太大 → 只在日志记一句，消息照旧当普通消息处理（不会把话吞掉）。

### 5.10 主动接话（可选）

「**主动接话**」页开总开关、调频率与语境权重；「**群聊**」页每张群卡片再勾「允许主动接话」。**两处都开才生效**。

### 5.11 权限与门禁

- **主人 QQ**：主人私聊豁免脱敏、群里「主人指令」、配置类命令都按它认。
- **门禁**（「其他」页，或直接在群卡片上改，同一份配置）：
  - 屏蔽群：整群不理；
  - 群内黑名单：这些人发的不回、不留档，优先级最高；
  - 群内白名单：该群只有名单内 + 主人能叫得动；
  - 全局允许用户：所有群 + 私聊一起限制（空 = 不限制）。
- **可选：QQ 线工具门**：如果桌面/profile 里装了全局工具插件（dsh-ops / agent-team 等），可加装 `dsh-onebot-qq-opsgate` 把 `ops_*`、团队、MCP 资源类工具从 QQ 会话里摘掉（只影响 QQ 线）；装法见 [安装与卸载](安装与卸载.md)。

**斜杠命令**（零 token；`/help` 任何人可用，其余仅主人）：

| 命令 | 权限 | 说明 |
|---|---|---|
| `/help` | 任何人 | 列出已注册命令（动态生成） |
| `/status` | 主人 | 连接 / 会话 / 插件状态 |
| `/reset` | 主人 | 重置**当前**这条 QQ 线会话 |
| `/resetall confirm` | 主人 | 重置所有 QQ 线会话（必须带 `confirm`） |
| `/cancel` | 主人 | 中止当前正在进行的回复 |
| `/quota` | 主人 | 查模型线路额度（需实例接入额度数据源，没有会明确提示） |
| `/history [N]` | 主人 | 拉本群最近 N 条记录进上下文（默认 50、上限 500；≈2.9K→7.6K token） |

### 5.12 看视频（可选，需要侧车）

- 「**看视频**」：群友直接发视频文件时，自动抽几帧交给模型，让它能描述画面；「**看视频链接**」：B 站/抖音链接同样抽帧（不用点开也能"看过"）。
- 抽帧/下载**不在插件进程里做**，需要一个本地 **解析侧车**（独立小服务，绑 127.0.0.1:3972，用 ffmpeg）。侧车没起或超时 → 自动降级，按普通消息处理，聊天不受影响。
- 开关与参数在控制台「**文件与图片**」页：侧车地址、只在被叫时才看、抽几帧、最长时长、每人/每群每小时额度（默认 0 = 不限）。
- 侧车不是本插件的一部分：装什么、怎么起由你决定；确认可信来源再用（它会在本机下载视频、调用 ffmpeg）。
- 侧车接口契约（`POST /read` 的请求/响应、失败码 `too_long`/`too_big`/`busy`/`nomatch`/`download_failed`）与最小实现说明见仓库 README 的「可选：解析侧车」一节。
- 额度默认不限，是因为没把旧机器人的限制搬过来；想防刷就在上面两项填数字。

## 6. 人设怎么写

### 6.1 一套人设 = 三个文件

| 文件 | 内容 |
|---|---|
| `<名字>.md` | **是谁、怎么说话**：身份、口头禅、必守、情绪反应、示范对话 |
| `<名字>.lines.txt` | **句池**：被戳/被叫/生图时的短句，一行一句，按 `# 节名` 分节 |
| `<名字>.wake.txt` | **唤醒词**：一行一个，群里说到就唤醒（不用 @） |

放在数据目录的 `personas/` 下；控制台「总览」点人设即可切换，或命令行：

```bash
node bin/dsh-onebot-qq.mjs persona use 蓝色大肥鱼
```

### 6.2 最省事的写法：让 AI 照模板写

模板随包提供，首次启动会投递到 `personas/_模板.md`。直接跟 DSH 说：

> 「照 `personas/_模板.md` 给我写一套人设，叫 XXX，性格是……」

### 6.3 写什么 / 不写什么

- **写**：身份、口吻、必守规矩（像真人那样说话）、几句示范对话。
- **不写**：工具怎么调、系统纪律、怎么收文件——那些是 DSH 和插件的事，不随人设变。

### 6.4 句池格式（`<名字>.lines.txt`）

```
## poke
戳我干嘛~
## callAck
在呢在呢
## imageBusy
画不过来啦，等会儿
```

节名用 `## ` 开头（`#` 开头是注释）；可用节名：`poke`（被戳）、`callAck`（被叫）、`imageAck` / `imageBusy` / `imageFail`（生图相关）等；没有的节会回落到 `_default.lines.txt` 或内置兜底，不会哑火。

### 6.5 唤醒词注意

一行一个（也支持逗号分隔）；**别放太泛的词**（比如单独一个「鱼」）——每命中一次就是一轮模型调用。自带唤醒词可以在控制台「唤醒」页点 × 删除（会改人设文件）。

## 7. 出问题先看这几条

> 完整排障手册见 [排错](排错.md)：先在控制台「运维」点 **🩺 一键诊断**，拿到脱敏报告再对号入座。

| 现象 | 先检查 |
|---|---|
| 收不到消息 / 不回 | 协议端 WS+HTTP 地址与 token（SnowLuma 两个都要）、「群聊」页是否屏蔽了该群、群里是否真的叫了它 |
| 状态一直断开 | 协议端里 QQ 是否在线（SnowLuma 看 `get_status.good`，`false` = 发得出收不进）；「运维 → 重新连接 OneBot」→「一键诊断」 |
| 生图报「未配置凭据」 | 「生图」页协议/地址/模型/Key；环境变量是否覆盖成空 |
| 生图失败后没再试 | 设计如此：失败只回一句，不自动重试（防重复扣费） |
| 文件没下载 | 默认「被叫才下」；确认这条消息是否叫到它，或去「文件与图片」页改策略 |
| 想卸载/回滚 | 见 [安装与卸载 §七、§八](安装与卸载.md)（备份文件形如 `config.json.bak-console-*`） |
